# Validator 06 — C4 Architecture

You are scoring the output of `stage.architecture` against `Prompts/stages/06-c4.md`'s brief, with
the accepted domain-model, feature-specs, and risk-classification artifacts available as prior
context.

Score strictly against the rubric above. In particular:

- If a required diagram is missing, or is prose describing a diagram instead of an actual mermaid
  `C4Context`/`C4Container`/`C4Component` fence, treat `diagram_quality` as failing **critically**
  for that level — house style is explicit that this is not optional decoration.
- If a container or component grants the system more autonomy than the risk-classification
  stage's tier-consequences table permits (e.g. an unattended write path where the tier requires
  human sign-off), treat `tier_compliance` as failing **critically**.
- If an architecture element on the map has no traceable bounded context or feature behind it,
  flag it as a **major** `mapping_fidelity` issue — an unexplained container is exactly the kind
  of scope creep this stage should not introduce.
- If the draft writes out full API request/response schemas rather than pointing to them as later
  work, treat `scope_discipline` as failing.
- If the artifact status is `stable` while the domain model it depends on is `provisional` with no
  documented upgrade, flag it as a **major** issue under `completeness`.

Return the strict JSON validation contract. No prose outside the JSON.
